## 3. 已验证的限制与异常（重要边界）

### 3.1 删除/回收站：`403 Forbidden CheckRouterAccessFailed`（影响大）
- `delete-file`、`trash-file`（CLI 与 REST 直连均一样）：`{"code":"Forbidden","message":"User not authorized to operate on the specified APIs CheckRouterAccessFailed"}`
- 官方 FAQ 原文口径：该错误 = 对应 API 路由未对当前凭证授权，重试无效，需域管理员授权。
- 即：当前企业版 API Key **即使继承超级管理员权限，也无法删除文件**（删除属额外路由授权项）。
- 影响：本次测试对象无法通过 API 清理，残留见 §6；未来同步引擎的"删除传播"依赖此项，需在域侧开通或另行确认。

### 3.2 子目录 `file/list` 与 `file/list_delta` 返回空（服务端数据面异常）
- Sync 空间 root 列表正常、`search`/`get`/`create`/`upload`/`update`/`move`/`copy` 全部正常，但：
  - `file/list`（parent=任一子目录）→ `items:[]`
  - `file/list_delta`（cursor 空）→ `items:[]`
- 已排除最终一致性（多次重试跨约 10 分钟仍空；root 列表反而已同步新对象）。
- 疑似该新建团队空间的"目录树/增量"数据面尚未就绪（Beta 风险）。
- 插件 cloud-path 解析（`--path/--parent-path` 上传/覆盖/移动）依赖 `list`，故**对子目录路径解析失败**；改用 `--file-id/--parent-file-id` 全流程可用。
- 对同步引擎：不应依赖 `file/list` 或 `list_delta` 做增量发现；可用 `search-file` + `file/get` 组合（见 §4 结论）。

### 3.3 覆盖写不保留历史 revision
- 覆盖后 `list-revision` 仅剩 1 条（`keep_forever=false`），旧 `revision_id` 的 `get-revision` 返回 `404 NotFound.Revision`。
- `revision_version` 覆盖后仍为 1（非递增计数）。同步状态判断应依赖 `content_hash(sha1)` 与 `updated_at/modified_at` 组合。

### 3.4 认证与端点细节
- `api.aliyunpds.com`（cn-shanghai 网关）上该企业域不存在 → **企业版数据面只走 `bj37789.api.aliyunfile.com`**。
- 裸域 `api.aliyunpds.com`/`api.aliyunfile.com` 不解析，仅通配 `{domain}.api.*`。
- 删除/回收站之外的 Bearer 直连 `POST /v2/...` 均可用（官方 OpenAPI 形状，企业版网关接受 `Authorization: Bearer uk-...`）。

## 4. 接入边界结论（指导书问题 5/6/7 的实证回答）

1. **企业版 API Key 只能通过 PDS Skill/官方插件使用？** 否。CLI 插件与**直接 HTTPS/V2 REST**（Bearer 直连企业版网关）均已实测可用，二者行为一致（如 delete 均 403）。
2. **有官方支持的非交互 CLI 调用方式？** 有：`aliyun-cli-pds 0.9.0` 的全部命令可无交互执行（`--cli-ai-mode` 或普通参数、JSON 输出、`--dry-run`），可用于本地自动化。
3. **有官方支持的直接 REST/SDK 方式可供未来 App 使用？** 有（实测）：`https://bj37789.api.aliyunfile.com/v2/*` + `Authorization: Bearer <uk-...>`；接口名与请求体同 PDS 2022-03-01 OpenAPI 形状（CreateFile/CompleteFile/UploadFile 分片流程、ListFile、SearchFile、GetFile、DownloadFile(redirect)、UpdateFile、MoveFile、CopyFile、DeleteFile）。但：
   - 企业版域只注册于 `*.api.aliyunfile.com` 网关，**与开发者版 `*.api.aliyunpds.com` 的 RAM AK 流程不是同一套**；本结论仅针对企业版网关实测结果。
   - DELETE/TRASH 路由被域级权限拦截（见 §3.1），需域管理员开通。
   - 无 OAuth 官方流程验证，`api_key` 直连是当前唯一实证方式。

## 5. 当前结论：是否适合作为自研同步 App 后端？

- **短期（个人单端→Web 读写场景）：可用**。认证（api_key Bearer）、空间识别（drive_id）、上传/下载/校验/覆盖/重命名/移动/复制、内容 hash 校验全部有效且可脚本化。
- **作为完整双向同步引擎后端：暂不满足**，主要缺口：
  1. 无可靠目录枚举/增量发现（`file/list` 子目录与 `list_delta` 空）→ 需依赖 `search-file` 全量扫描 + 本地状态比对兜底；
  2. 无删除能力（403）→ 删除传播不可做；
  3. revision 历史默认不保留 → 版本级冲突还原不可依赖；
  4. API Key 为 Beta/限免，接口与计费可能变化；
  5. 当前 Key 继承超管权限，生产接入前必须换成最小权限、仅授权 Sync 空间的 Key（控制台"自定义"模式）。

### 6.2 对同步引擎的建议（更新）
- **增删改查的影子操作**：Create=create-file+upload、Update=同 file_id 覆盖写、Rename/Move/Copy 均可用；**Delete=move 到 `_trash_chenthre_sync`（约定名，不可与其他正常目录重名）**，并记录 `moved_to_trash=true` 之类的本地状态。
- **枚举**：不要依赖 `file/list`(子目录) 或 `list_delta`；以 `file/search` 全量扫描 + 本地状态库比对；等阿里云修复或开通后再切换。
- **重名**：移动/复制同名对象需显式 `--check-name-mode auto_rename`，并接受服务端追加 `_YYYYMMDD_HHMMSS` 后缀。
- 归档目录本身不要用 rename（避免破坏约定）。

### 6.3 严格复验：排除测试代码问题（针对「子目录 list 为空」质疑）

用户质疑测试可能有误，追加以下独立验证，全部证明**请求/参数/流程正确，问题在服务端**：

1. **CLI dry-run 请求体核对**：`list-file` 发送 `POST /v2/file/list` body 恰为 `{"drive_id":"101","parent_file_id":"<id>"}`（root 与子目录一致，仅 parent 不同），无隐藏参数。
2. **纯 REST 全链路重建**（`strict_probe.py`，不用插件路径解析）：新建 `probe_rest` 目录 → `create-file` → PUT 分片 → `complete`，随后：get-file 正常（size=43）、root list 实时可见新目录、**子目录 list 仍空**、search 约 1 分钟后可见。
3. **请求形式矩阵**（`list_matrix.py`）：标准 body（空）、URL query（400：报错含 `for cpp path domain`）、GET（404）、加 `x-pds-domain-id` 头（空）、`v2/batch` 包裹（`403 CheckRouterAccessFailed`，batch 路由亦未授权）、`api-vpc` 端点（公网不可达）。
4. **权限核对**：目录 `get-file` 的 `action_list` 含 `FILE.LIST`（权限齐备）。
5. **决定性实验——可见性随父目录变化**：`hello_rest.txt` 位于子目录时 list 该目录=空；**move 到 root 后 list root 立即可见**；**move 回子目录后 list 又=空**；search/get 全程正确。同一文件、同一 Key、同一接口，仅父目录变化即改变 list 结果 → 服务端对「子目录作为 parent」的查询数据面异常，与本地测试无关。
6. **企业空间对照（补充发现）**：`search-drive` 找到企业空间为 **`drive_id=2`（Chenthre Cloud）**；API Key 访问其 root list 返回 `403 ForbiddenNoPermission.File`。→ **当前 API Key 权限范围仅 Sync 团队空间（drive 101）**，这也解释了 `list-all-drives` 只返回 Sync（该接口按 Key 可见空间枚举）。

## 7. 下一步建议

1. 在控制台将当前宽权限 Key 替换为 **Sync 专用最小权限 Key**（自定义权限，仅 drive 101），并设置有效期。
2. 向阿里云侧确认三项：（a）DELETE/TRASH 的 `CheckRouterAccessFailed` 如何在企业版域开启；（b）团队空间子目录 `file/list`、`list_delta` 为空是否为已知问题/需开通能力；（c）`recycle_bin_config.delete_trash_normal_file_disabled=true` 与 `multi_revision_config.enabled=false` 两个域配置对删除/版本行为的影响。
3. 若时间敏感，可先用 `search-file` 全量扫描 + 本地 `file_id/content_hash` 状态库做单向上传下载原型（在隔离目录内）。
4. 跟踪 Beta 功能正式化后的计费与认证形式变化。
